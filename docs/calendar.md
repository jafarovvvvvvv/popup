# Календарь

Слева сетка месяца, справа встречи выбранного дня.

Сетка показывается **всегда**, даже если никакой календарь не подключён: числа
и дни недели полезны сами по себе — «какое число в четверг» не требует ни
аккаунта, ни согласия. Сегодняшнее число обведено, выбранное залито, под днями
со встречами стоит точка. Месяцы листаются стрелками или колесом мыши; кнопка
«Сегодня» возвращает обратно. Клик по числу соседнего месяца туда и переходит.

Подключённый календарь добавляет к сетке встречи — и только.

## Откуда брать встречи

На macOS Cyclop берёт их из EventKit — общего системного календаря. В
Windows такого нет: у Outlook свой, у почтового приложения свой, у календаря в
браузере вообще никакого. Поэтому источник задаётся явно, и путей два.

## Путь первый: ссылка на календарь (рекомендуется)

Тридцать секунд, никаких приложений в Google Cloud, никаких согласий.

1. Google Календарь → **Настройки** → выбери календарь слева → **Интеграция
   календаря** → скопируй **Секретный адрес в формате iCal**.
   (Outlook: **Календарь → Общий доступ → Опубликовать календарь → ICS**.
   Яндекс: **Настройки → Экспорт → ссылка iCal**.)
2. Вставь её в `%APPDATA%\Popup\settings.json`:

```json
{
  "calendarIcsUrl": "https://calendar.google.com/calendar/ical/…/basic.ics"
}
```

Перезапускать ничего не надо — панель следит за файлом. Вкладка календаря
наполнится сама.

Ссылка секретная: кто её знает, тот видит календарь. Храни её как пароль, а
если утекла — в тех же настройках Google есть «Сбросить ссылки».

Что разбирается: обычные встречи, события на весь день, время по Гринвичу и
местное, повторы (каждый день / неделю / месяц / год, с шагом, по дням недели,
с ограничением по числу и дате) и отменённые даты в ряду. Кнопка «войти» ищется
в месте и описании — Zoom, Meet, Teams, Whereby, Jitsi, Телемост, Discord.

## Путь второй: вход через Google

Нужен, если хочется не одну ссылку, а несколько календарей и мгновенное
обновление. Стоит дороже: Google считает доступ к календарю **чувствительным**,
и приложение либо проходит проверку, либо живёт в режиме тестирования.

1. [console.cloud.google.com](https://console.cloud.google.com/) → создай проект.
2. **APIs & Services → Library** → **Google Calendar API** → **Enable**.
3. **OAuth consent screen**: тип **External**, статус публикации — **Testing**.
4. **Audience → Test users** → добавь свой адрес.
5. **Credentials → Create credentials → OAuth client ID** → тип **Desktop app**.
6. В `settings.json`:

```json
{
  "googleClientId": "…….apps.googleusercontent.com",
  "googleClientSecret": "……"
}
```

Секрет исчезнет из файла при первом чтении — переедет в `googleClientSecretEnc`
под DPAPI. Так и должно быть.

Затем вкладка **Календарь** → **Подключить Google Календарь**.

### Если Google не пускает

**`Ошибка 401: invalid_client`** — идентификатор скопирован с ошибкой. Чаще
всего суффикс `.apps.googleusercontent.com` попал в него дважды: в Google Cloud
он стоит вплотную к подписи. Panel чинит это сама, но если строка испорчена
иначе, вкладка так и скажет.

**`Ошибка 403: access_denied`** — приложение в режиме тестирования, а твой
адрес не в списке допущенных.

**`Ineligible accounts not added`** при попытке добавить себя в Test users:

- Статус публикации — **In production**. В этом режиме тестовых пользователей
  не бывает вовсе, поле неактивно. Верни **Testing**.
- Адрес записан **с точками**: Gmail их игнорирует, а это поле — нет.
  `Name.Surname@gmail.com` и `namesurname@gmail.com` для Google здесь разные
  строки. Впиши вариант без точек и в нижнем регистре.
- Аккаунт уже владелец проекта. Владельцу тестовым пользователем быть не нужно
  — он и так внутри; но если доступ всё равно не даётся, проще взять первый
  путь.

Подробности любой ошибки — в `%APPDATA%\Popup\logs\popup.log`.
