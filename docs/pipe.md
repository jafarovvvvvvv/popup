# Канал: как чужой процесс говорит с панелью

Popup слушает именованный канал `\\.\pipe\popup`. Любой процесс, запущенный от
твоего имени, может подключиться к нему и что-нибудь положить в панель.

Это вторая половина расширяемости, дополняющая [плагины](plugins.md), и разница
между ними принципиальная:

| | Плагины | Канал |
|---|---|---|
| Кто кого запускает | Popup запускает плагин | Процесс уже работает сам по себе |
| Кто начинает разговор | Popup: «нарисуйся» | Процесс: «покажи вот это» |
| Для чего | Своя вкладка в панели | Сообщить, что идёт работа; положить файл, текст, заметку |

Заводить плагин ради программы, которая и так запущена, значило бы просить
панель запускать то, что уже работает. Для этого и есть канал.

## Живая активность

Главное, ради чего он появился. Пока в системе что-то происходит, панель
показывает узкую полоску наверху экрана — не раскрываясь и не закрывая работу.

```json
{"type":"activity","source":"localwhisper","name":"LocalWhisper",
 "tone":"live","label":"0:07","actions":[{"id":"stop","label":"Стоп"}]}
```

| Поле | Смысл |
|---|---|
| `source` | Кто говорит. По нему полоска и убирается — чужую не тронет |
| `name` | Человеческое имя источника |
| `tone` | `live` — идёт прямо сейчас (красная точка, бегущая волна)<br>`busy` — работа без участия человека (серые дышащие точки)<br>`ok` — получилось (зелёная галка, гаснет сама)<br>`idle` — убрать полоску |
| `label` | Короткая подпись справа: таймер, процент, имя файла |
| `actions` | Кнопки. Появляются в шапке раскрытой панели. Можно писать `["stop"]` вместо объектов |

Синонимы принимаются: `recording` = `live`, `processing` = `busy`,
`done` = `success` = `ok`, `none` = `idle`.

Нажатие на кнопку уезжает обратно тому же процессу:

```json
{"type":"action","source":"localwhisper","id":"stop"}
```

Полоска **не принимает клики в свёрнутом виде** — она стоит поверх чужих окон,
и съедать по ним клики было бы обманом. Кнопки живут в шапке: наведи курсор,
панель раскроется, кнопка окажется на том же месте, где была полоска.

Оборвавшееся подключение убирает свою полоску само: «идёт запись» без того, кто
записывает, — это не состояние, а мусор на экране.

## Остальные команды

```json
{"type":"clip","text":"…"}             положить в буфер обмена
{"type":"shelf","paths":["C:\\…"]}     положить файлы на полку
{"type":"note","text":"…"}             завести заметку
```

Набор нарочно весь про «положить сюда». Ничего читающего в канале нет: панель
принимает, но не выдаёт наружу ни истории буфера, ни календаря, ни сниппетов.

## Клиент на Python

Канал в Windows открывается как обычный файл.

```python
import json

with open(r"\\.\pipe\popup", "r+b", buffering=0) as pipe:
    def push(msg):
        pipe.write((json.dumps(msg, ensure_ascii=False) + "\n").encode("utf-8"))

    push({"type": "activity", "source": "build", "tone": "busy", "label": "сборка"})
    ...
    push({"type": "activity", "source": "build", "tone": "ok", "label": "готово"})
```

Если панель не запущена, `open` бросит `OSError` — это нормальное состояние, а
не ошибка: программа просто работает как обычно. Готовый пример с
переподключением, чтением ответов и опросом через `PeekNamedPipe` —
`popup_bridge.py` в LocalWhisper.

**Читать ответы блокирующим чтением нельзя**, если в том же процессе идёт
запись: дескриптор канала не перекрывающийся, и блокирующее чтение заморозит
запись из другого потока. Опрашивай `PeekNamedPipe`, как это делает мост.

## Клиент на C#

```csharp
using var pipe = new NamedPipeClientStream(".", "popup", PipeDirection.InOut);
pipe.Connect(1000);
using var writer = new StreamWriter(pipe) { AutoFlush = true };
writer.WriteLine("""{"type":"clip","text":"привет"}""");
```

## Про безопасность

Канал открыт всему, что работает от твоего имени, — тот же уровень доверия, что
и папка плагинов. Это осознанно: канал умеет только класть в панель и не умеет
ничего из неё доставать.
